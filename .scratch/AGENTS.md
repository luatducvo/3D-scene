# Ticket guidance

Read [root AGENTS.md](../AGENTS.md) and [current status](../docs/project-status.md)
first, then the ticket and the linked current contract before implementation.

Tickets live in `s3d-v3/issues/`. Tickets 01–24 describe the initial delivery;
ticket 25 and ADR 0009 supersede the old v1/inbox/S1-alignment requirements.
Preserve historical acceptance evidence while clearly annotating superseded
criteria. Derive current input behavior from the v2 Package contract.

For a completed ticket, mark status/acceptance against actual evidence and link
the verification record. Update `docs/project-status.md` for remaining or newly
completed work. Keep discussion/design notes distinct from accepted requirements.
